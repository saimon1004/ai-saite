# 「顔の見えるFAQ」LP 設計仕様

作成日: 2026-07-30
対象: `sai-mon.co.jp/video-faq/`（新規1ページ）

## 1. 背景

ほんりゅう（松本さん・matsumoto@syou-getsu.biz）が提供する動画FAQチャットボットSaaSの代理店LPを起点に、SAIMONが自社サービスとして販売するためのLPを新設する。元LP: https://www.syou-getsu.biz/lp/video-faq/ （代理店募集向け）。

SAIMONは既に代理店契約済み（内諾あり）。本LPはエンド顧客向けの販売LPであり、元LPの「代理店募集」構造は引き継がない。

### 実機調査で確認した事実（2026-07-30）

| 項目 | 実測値 |
| --- | --- |
| ウィジェット配信元 | `https://faq-saas-widget.pages.dev/faq-chatbot.js`（Cloudflare Pages） |
| API | `https://faq-saas-api.takashi-matsumoto-jp.workers.dev`（Cloudflare Workers） |
| エンドポイント | `/api/config/{tenant}`（設定取得）、`/api/events`（計測送信） |
| ファイルサイズ | raw 55,289 bytes / gzip 18,190 bytes |
| 対応機能 | tenant別設定・カテゴリ・質問・brandColor・字幕(caption)・muted・autoplay・poster/thumbnail |
| 管理画面 | `https://faq-saas-admin.pages.dev/#/login` |
| デモサイト | `https://sunrise-travel-recruit.vercel.app`（HTTP 200・稼働中） |

**デモサイトは架空企業のサンプル**（canonical が `example.com` を指す）。実在の顧客サイトではない。したがって「導入企業」「運用中の実績」としては扱えない。

### SAIMON自社サイトの既存チャットボットとの関係

`ai-saite` リポジトリには既に**自作の動画FAQチャットボット**が存在する（`public/faq-chatbot.js` / 44,774 bytes / 完全セルフホスト・外部API不使用）。`src/layouts/BaseLayout.astro:117-139` で `window.FAQChatbotConfig` 経由で設定を渡す構成。カテゴリ・質問・字幕・ミュートに対応するがSaaS層（テナント管理・計測・管理画面）を持たない。ほんりゅう版とは別実装（ハッシュ不一致）。

現在の挨拶動画（`public/videos/chatbot/greeting.mp4`・16秒）は「実はこのチャットボットも研修の中で作れるようになります」と喋っており、**研修事業の営業導線として機能している**。

**決定: 自社ウィジェットは現状維持する。** 研修導線を壊さないため差し替えない。そのかわり本LPページ内では非表示にする（別実装のものが右下に出ていると訪問者が商品と誤認するため）。「自社を第1号導入事例にする」案は採用しない。

### 自社ウィジェットのソースが存在することの確認（重要・再検討不要）

`faq-chatbot-widget/`（**未コミット・未追跡**）に自作ウィジェットのソース一式が存在する。

- React + Vite + Tailwind、12コンポーネント（`FAQChatbot.tsx` / `VideoPlayer.tsx` / `CategoryList.tsx` / `QuestionList.tsx` / `ContactForm.tsx` 他）、ビルド済み `dist/`
- 設定は外部差し替え可能（`src/config/defaults.ts`：カテゴリ・質問・動画・字幕・挨拶文・音声ON/OFF）
- キーボード操作・フォーカストラップ実装済み
- **`docs/setup-html.md` / `setup-wordpress.md` / `setup-nocode.md` の3本があり、冒頭に「納品物」と記載**。第三者への納品を前提に作られている

ほんりゅう版との差はSaaS層（セルフサービス管理画面・視聴計測ダッシュボード・マルチテナント払い出し）のみで、ウィジェット本体の機能は同等。

**この事実を踏まえた上で、2026-07-30に「ほんりゅう版を代理店として売る」と判断した。** 自社版を売る選択肢（マージン100%・値付け自由・改善を自社で回せる）と比較検討した結果の決定であり、本仕様の実装中に再検討しない。将来方針を変える場合はこの節を更新する。

## 2. 確定した決定事項

| 項目 | 決定 | 備考 |
| --- | --- | --- |
| SAIMONの立ち位置 | ほんりゅうの代理店として販売 | 契約済み／内諾あり |
| サービス名 | **顔の見えるFAQ** | 用途（FAQ）と差別化（人が答える）が名前で完結 |
| ブランド表記 | SAIMONのサービスとして提供（提供元は表に出さない） | ホワイトラベル前提。契約上の可否は要確認 |
| ターゲット業種 | **保険・共済・冠婚葬祭互助会・葬祭** | 採用は除外（親交の深い企業が同事業を営むため） |
| 読み手 | 加入者対応部門・コールセンター・Web担当 | 決裁は部門長〜経営層 |
| 料金表示 | 金額を出さず「要相談」 | 卸値未共有 |
| 実演デモ | 既存の採用デモをそのままリンク | 業種は異なる旨を正直に明記 |
| 導入事例 | **掲載しない** | 実績ゼロのため書けば虚偽になる |

### 業種選定の根拠

保険・互助会・葬祭を選んだ理由は3点。

1. **実チャネルがある。** アルファクラブ武蔵野（互助会）、葬儀保険「みんなのキズナ」で既に接点があり、サブスクデザインも保険/互助会特化を掲げている。新規集客なしで提案できる。
2. **商品特性が噛み合う。** 「解約返戻金」「保障の範囲」「申込みの流れ」は文章だと極端に分かりづらく電話問い合わせが集中する。かつ聞きにくい質問（費用、家族に何が起きるか）が多く、人が動画で答える価値が他業種より明確に高い。
3. **単価が通る。** 1件のLTVが数十万円規模のため月額数万円の説明がつく。ECのようにCVR貢献度で毎月値踏みされる構造にならない。

ECを避けた理由: SAIMONに事例・チャネルがなく既存の接客チャットボット（チャネルトーク、ZEALS等）との機能・価格比較に落ちる。動画FAQ単体のCVR貢献を証明しにくく解約されやすい。動画準備コストが商品点数に比例して膨らむ。

## 3. LP構成

全11セクション。各セクションの意図とコピー方針を示す。

### S1. ヒーロー

- **H1 = 「顔の見えるFAQ」**（frontend-ui-rules: LPのH1はブランド名/商品名。説明的な文言は補助コピーへ）
- 補助コピー: 解約返戻金、保障の範囲、申込みの流れ。文章では伝わりきらない質問に、担当者の顔と声で答える。Webサイトにタグを貼るだけで導入できる旨。
- CTA 2本: 「実装デモを触る」（デモサイト・別タブ）／「無料相談」（ページ内フォームへ）
- 背景は**生成ビットマップ画像**（グラデ/SVGのみは禁止）。ヒーロー文をカードに入れない。次セクションの気配が見える高さにする（PC・ワイドPC・モバイル）。
- 画像の方向性: 落ち着いた応接空間で年配の方が説明を受けている、またはスマホを見る手元。**葬祭を扱うため陰鬱・喪のモチーフは避け、穏やかで敬意のあるトーンにする。**

### S2. 課題（4項目）

この業界固有の痛みで刺す。

1. 「解約したらいくら戻るのか」を電話で何度も説明している
2. 資料請求・問い合わせの前に離脱される（文章だけでは不安が消えない）
3. 高齢の加入者がWebの文章を読んでくれない
4. 説明の質が担当者ごとにばらつく（コンプライアンス上のリスク）

4番目はこの業界に特に効く論点。他業種向けLPでは出てこない差別化ポイント。

### S3. 仕組み（4ステップ）

1. Webサイトにタグを貼る
2. 管理画面で質問と回答動画を登録
3. 加入者が質問をタップして動画で回答を見る
4. 視聴データを管理画面で確認

### S4. 実装デモ

デモサイト（`https://sunrise-travel-recruit.vercel.app`）へのリンク。

**業種のズレを隠さず扱う。** 「別業種（採用サイト）での実装例です。ウィジェットの動作・操作感は業種を問わず同じで、質問と動画の中身が変わります」と明記する。架空企業のサンプルサイトである旨も曖昧にしない。

### S5. この業界に効く理由（4項目）

1. 聞きにくい質問こそ、人が答えると伝わる
2. 高齢の加入者には、読ませるより見せるほうが届く
3. 説明を動画で固定すれば、担当者による説明のばらつきがなくなる
4. 同じ質問への電話応対が減る

### S6. 機能（6項目・実測ベース）

**元LPの数値をそのまま転記しない。** 元LPは「gzip後14KB」と記載しているが実測18,190 bytes。実測値または定性表現を使う。

1. タグを貼るだけで導入（HTMLが書けるサイトならどこでも）
2. ブランドカラー対応（`brandColor`）
3. カテゴリ×質問の階層管理
4. 字幕対応（音声オフでも読める＝高齢層・電車内での閲覧に効く）
5. 視聴計測（起動回数・再生数・視聴完了率・人気質問・UU）
6. モバイル最適化（スマホ全画面／PC右下フローティング）

軽量性は「サイト本体のレンダリングをブロックしない独立JS（実測 gzip 約18KB）」と実測値で書く。

### S7. 動画はどう用意するか（SAIMON独自価値）

**元LPとの決定的な違い。** ほんりゅうのLPは「別途動画制作サービスとして対応可能」と一行で流しているが、これは導入検討者にとって最大のハードル。SAIMONは研修・制作事業を持つため、質問設計から納品までまとめて請けられる。他の代理店との差もここでつく。

提供範囲を3段階で示す:

1. **質問設計から**: 問い合わせ履歴・FAQページから質問を洗い出し、優先順位を付ける
2. **台本作成**: 話す内容を原稿化する（コンプライアンス確認を通しやすい形にする）
3. **撮影または生成**: 担当者の実写撮影、またはAIアバターでの生成に対応

### S8. 導入の流れ（4ステップ）

1. 無料相談（現状の問い合わせ内容をヒアリング）
2. 質問の設計と優先順位付け
3. 動画の準備（台本→撮影/生成）
4. タグ設置して公開、視聴データを見ながら質問を追加

### S9. 料金

**金額は書かない。** 料金が何で決まるか（質問数・動画本数・動画制作の範囲・運用代行の有無）を説明し、個別見積へ導く。「初期費用＋月額」の構成であることまでは書ける。

### S10. FAQ（9問）

| # | 質問 | 回答の要点 |
| --- | --- | --- |
| 1 | 保険商品の説明に使って法令上の問題はないか | **よくある質問への補助説明としての利用を前提**とする。重要事項説明・契約締結前交付書面の代替にはならない。募集行為に当たる内容を扱う場合は貴社コンプライアンス部門の確認を前提に原稿レビュー工程を入れる |
| 2 | 高齢の加入者でも操作できるか | 質問をタップするだけ。字幕付きで音声オフでも読める |

| 4 | 動画は誰が作るのか | SAIMONが質問設計・台本から対応。実写・AIアバター両対応 |
| 5 | 既存サイトへの影響 | 独立JS。レンダリングをブロックしない。実測 gzip 約18KB。CSSは独自スコープ |

## 4. 技術仕様

### ファイル構成

```
src/pages/video-faq.astro              新規（ページ本体）
public/video-faq/styles.css            新規（スコープ .vfaq-lp-scope）
public/video-faq/assets/hero.jpg       新規（gen-image で生成）
public/video-faq/assets/hero-m.jpg     新規（モバイル用）
src/data/navigation.ts                 修正（ナビ項目追加）
```

URLは `/video-faq/`。サービス名は「顔の見えるFAQ」だがURLは検索されやすい一般語にする（サービス名はブランド層）。

### 既存規約の踏襲

`subsc-design.astro` と同じ構成に揃える。

- `BaseLayout` + `Header` + `Footer` を import
- CSSは `public/` 配下に外部ファイルとして置き、`cssVersion` でキャッシュバスト（Xserverが1年キャッシュするため）。初期値 `20260730-v1`
- 全セレクタに `.vfaq-lp-scope` 接頭辞を付けて他ページへの影響を防ぐ
- JSON-LD は `@graph` 方式で Organization（既存 `@id` を参照）・Service・FAQPage・BreadcrumbList を出す

### 自社チャットボットの非表示

既存3ページ（`subsc-design.astro:127`、`subsc-design/terms.astro:12`、`subsc-design/partner.astro:127`）と同じ方法で隠す。

```astro
<style is:global>#faq-chatbot-root { display: none !important; }</style>
```

理由: 別実装の自作ウィジェットが右下に出ていると、訪問者が「これが売っている商品か」と誤認する。

### ナビゲーション

`src/data/navigation.ts` に「顔の見えるFAQ」を追加する。現在8項目なので9項目になり、モバイルで窮屈になる可能性がある。実装後にモバイル幅で実測し、崩れる場合は以下を検討する（本仕様の範囲外・別途相談）。

- サービス系3項目（HP制作内製化／サブスクデザイン／顔の見えるFAQ）を「サービス」にまとめる
- ナビから外し、トップページのサービス一覧からの導線に絞る

### パレット・書体

SAIMONブランド色を主色、Tealをアクセント、中立グレー階調で階層を作る（単一色相支配を避ける）。

```css
--navy: #0d0084;      /* ブランド主色：見出し・強調 */
--navy-deep: #070046; /* ヒーロー暗部・オーバーレイ */
--teal: #31b9b5;      /* アクセント：CTA・アイコン・区切り */
--ink: #1b2430;       /* 本文 */
--muted: #5d6672;     /* 補助文 */
--line: #e3e1dc;      /* 罫線 */
--paper: #faf9f7;     /* 背景：わずかに暖色寄りの白（信頼業種の柔らかさ） */
--white: #ffffff;
```

`paper` を冷たいグレーではなく暖色寄りの白にすることで、色相を増やさずに保険・葬祭に必要な柔らかさを出す。

書体は**ゴシック主体**（Inter＋Noto Sans JP。サイト全体のトークンと同じ）。`subsc-design` は明朝主体（Shippori Mincho B1）の格式トーンなので、書体を変えることで別サービスであることが一目で分かる。

### 日本語組版（必須）

`.claude/references/jp-typography-rules.md` に全面準拠する。

- 日本語の文をソースコード内で途中改行しない（改行が半角スペース化して折り返し点になる）
- 見出し（h1〜h3）: `text-wrap: balance` + `word-break: auto-phrase`
- リード文: `text-wrap: pretty` + `word-break: auto-phrase`
- 本文・カード文・FAQ回答: `text-wrap: pretty` + `word-break: auto-phrase`、モバイル（〜640px）は `word-break: normal` に戻す
- **Safari対策**: `auto-phrase` はChromium専用。見出し・FAQ・主要リード・重要語句は `.no-break`（nowrap）で文節単位に塊化し、**隣接する塊の間には必ず `<wbr />` を入れる**
- BudouX（`applyToElement`）を本文・リードに適用する。**`budoux` は既に導入済み（`^0.8.4`）**。`src/pages/index.astro:80-117` と `src/pages/subsc-design.astro:1062` に `.jp-budoux` クラスでの適用パターンが確立しているので、それをそのまま踏襲する（新規導入・独自実装は不要）
- 長い注記は中央揃えにしない（`text-align:left` + `max-width` + `margin-inline:auto`）
- 幅制限ブロックには `margin-inline: auto`
- セクション余白: PC 60px / モバイル 44px、見出しブロック下 32px
- **styles.css を変更したら必ず `cssVersion` をバンプしてから検証する**

### UI設計（必須）

`.claude/references/frontend-ui-rules.md` に準拠する。LPは明示依頼なのでLP回避ルールは適用しない（例外1）。ブランド指定があるのでパレット回避ルールに優先する（例外2）。

- カードのinカード禁止／セクションをカード化しない。カードは反復アイテムのみ。角丸8px以下
- グラデーションオーブ・ボケ玉装飾を使わない
- ヒーローに生成画像を使う（グラデ/SVGのみは禁止）。ヒーロー文をカードに入れない
- 本文フォントサイズを `vw` でスケールさせない
- UIに機能説明文・使い方文を書かない

アイコンについては規約から意図的に外れる。規約は lucide を優先せよとするが、**このリポジトリにアイコンライブラリは導入されていない**（`grep lucide src/` が0件）。既存LPはインラインSVGで統一されており、1ページのために新規依存を追加するのはスコープ拡大になる。規約1「既存の規約・既存アプリのデザインとの一貫性を最優先」に従い、既存LPと同じインラインSVG方式にする。数は最小限に抑える。

## 5. 書かないこと（虚偽防止）

| 書かないもの | 理由 |
| --- | --- |
| 導入企業名・導入社数・導入実績 | 実績ゼロ |
| 「運用中のサイトで動いています」 | デモは架空企業のサンプルサイト |
| 「gzip後14KB」 | 元LPの記載。実測は18,190 bytes |
| 具体的な金額・プラン表 | 卸値未共有 |
| 最低契約期間・解約条件の具体値 | 卸契約条件が未共有 |
| 効果数値（応募率○%改善、離脱率○%減 等） | 検証データなし |
| 「重要事項説明を動画で行えます」 | 保険業法上の説明義務を代替できない |

## 6. 未確定事項（実装をブロックしないが要確認）

1. **ホワイトラベル可否** — SAIMON名義で提供元を出さない形が契約上OKか。NGなら「提供: ほんりゅう」の表記を足す
2. **卸値** — 決まれば料金セクションを金額入りに差し替える（成約率は上がる）
3. **SAIMON名義デモテナント** — 管理画面（`https://faq-saas-admin.pages.dev/#/login`）で互助会・保険のモックサイト用テナントを作れば業種の合った実演になる。認証情報は齋本さんのみが扱う（Claudeは認証情報を入力しない）
4. **Meta Pixel** — `recruit-hp.astro` にはPixelが入っている。本LPで広告を回す予定があるなら追加する。予定がなければ入れない
5. **ナビ9項目のモバイル表示** — 実装後に実測して判断

## 7. 検証計画

「ビルドが通った」を完了と見なさない。

1. `npm run build` がエラーなく通る
2. `preview_start`（`~/Claude Code/.claude/launch.json` の `ai-saite-dev`）でローカル起動
3. **Safari相当を再現して実測**: `.vfaq-lp-scope *{word-break:normal!important}` を注入し、リビール演出を無効化（`[class*="rv"]{opacity:1!important;transform:none!important}`）してPC幅・モバイル幅でフルページ撮影
4. 主要ブロックの `scrollWidth - clientWidth > 0`（はみ出し）を実測して**0件**にする
5. 行充填率: `Range.getClientRects()` で「最終行以外で右側が28%以上空く行」をPC・モバイル両方で検出して0件にする
6. 左右対称性: 主要ブロックの `getBoundingClientRect()` で左右余白の一致を確認
7. 生成したヒーロー画像とフルページスクショを **Read（画像）で目視確認**
8. `frontend-ui-rules.md` の完成前セルフチェック13項目を通す
9. `jp-copy-reviewer` エージェントで日本語コピーを校正（対外公開物のため）
10. `security-reviewer` エージェントで公開前差分をレビュー
11. デプロイ後、本番URL `https://sai-mon.co.jp/video-faq/` を実測して再確認

## 8. デプロイ

`reference_aisaite_deploy.md` の手順に従う。

1. `npm run build` でビルド確認
2. `git add` で変更ファイルのみステージ
3. `git commit`
4. `git push origin main` → GitHub Actions（`.github/workflows/deploy-xserver.yml`）が自動デプロイ
5. `gh run watch <run_id> --repo saimon1004/ai-saite` で完了を待つ
6. 本番URLで実測確認

**push はユーザー確認後に実施する。**
